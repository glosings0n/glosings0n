Eliminating the AI Verification Tax with Agentic Engineering

1. Context & The "Why": Escaping the Vibe-Coding Verification Tax

Over 79% of Flutter and Dart developers now use AI coding assistants daily. Yet across production mobile teams, a painful paradox has emerged: while raw code generation is faster than ever, engineers spend hours fixing hallucinated pub.dev APIs, unbounded RenderFlex layout overflows, leaked BuildContext references across async gaps, and broken layer boundaries where database DTOs leak directly into UI widgets.

This hidden productivity drain is known as The Verification Tax. It happens when developers rely on unconstrained Vibe-Coding (prompting an LLM in a vacuum without compiler grounding or architectural contracts) instead of Agentic Engineering.

Core Thesis of Agentic Engineering

An AI coding agent is only as reliable as the tools it can invoke, the architectural constitution it must obey, and the deterministic verification loop that gates its output.

Step 2 of 8 | Model Context Protocol Integration

Connecting the Official Dart & Flutter MCP Server

Without tool grounding, an LLM treats Dart like untyped plain text. It frequently invents named parameters that do not exist in your installed version of flutter_bloc or MaterialApp, and it cannot see runtime layout exceptions thrown inside your running emulator.

Starting with Dart 3.8, the Dart SDK ships with a first-party Model Context Protocol server invoked via dart mcp-server. It bridges your coding agent directly to the Dart Analysis Server, the pub package manager, and the Dart Tooling Daemon (DTD) connected to your running Flutter VM.

AST Symbol Lookup signature_help / hover Lets the agent inspect exact constructor parameters and doc comments from your local .pub-cache.
Package Management pub / pub_dev_search Searches pub.dev for current package versions and executes flutter pub add safely.
Runtime Inspection get_widget_tree / get_runtime_errors Reads live RenderFlex overflow trees and active stack traces directly from the running Flutter app.
Stateful Iteration hot_reload / hot_restart Applies edits to the running VM in sub-second cycles and verifies that runtime errors disappear.

Some CLI and editor MCP clients do not yet implement the MCP roots/list capability natively. Passing --force-roots-fallback allows the agent to register workspace roots dynamically via tool calls so analyze_files and pub always resolve your project directory accurately.

Step 3 of 8 | Project Governance & System Invariants

Engineering a Zero-Drift AGENTS.md Constitution

dart mcp-server tells the agent whether your code compiles, but it does not tell the agent how your team architects software. Without explicit architectural rules, an agent will happily mix HTTP calls inside StatefulWidget.build(), hardcode hex colors across 40 files, or swallow exceptions with empty catch (_) {} blocks.

AGENTS.md is the open standard for repository-level instructions read automatically at the start of every session by modern coding agents. Think of AGENTS.md as a compiler constitution for agent behavior: it must be concise, unambiguous, and strictly focused on global invariants that apply to every task in the repository.

Anatomy of a High-Signal Flutter AGENTS.md

  • Keep it under 150 lines: Every token in AGENTS.md is injected into every conversation turn. Put universal invariants in AGENTS.md and move task-specific playbooks into modular SKILL.md files (Step 4).
  • Define Strict Layer Dependency Direction: Explicitly forbid lib/domain/ from importing package:flutter/ or data-layer DTOs.
  • Mandate Exhaustive Pattern Matching: Require Dart 3 sealed class hierarchies for states and results so the compiler forces exhaustive switch expressions in widgets.
  • Define the Verification Gate: Instruct the agent that no task is complete until analyze_files (or flutter analyze --fatal-infos) and flutter test return zero issues.

Anatomie d'un AGENTS.md Flutter à Fort Signal

  • Définir la Direction Stricte des Dépendances : Interdire explicitement à lib/domain/ d'importer package:flutter/ ou des DTOs de la couche de données.
  • Imposer le Pattern Matching Exhaustif : Exiger des hiérarchies sealed class Dart 3 pour les états et résultats afin que le compilateur impose des expressions switch exhaustives dans les widgets.
  • Définir la Porte de Vérification : Instruire l'agent qu'aucune tâche n'est terminée tant que analyze_files (ou flutter analyze --fatal-infos) et flutter test ne retournent pas zéro erreur.

AGENTS.md | Root Architectural Constitution for Flutter Agents MARKDOWN 
# AGENTS.md | Flutter & Dart Engineering Constitution

These architectural and verification rules are mandatory across all files in this repository.

## 1. Strict Layered Architecture & Dependency Rule
- `lib/domain/`: Pure Dart only. Contains immutable entities, value objects, `sealed class Result<T>`, and `abstract interface class` repository contracts.
  - FORBIDDEN in `lib/domain/`: Never import `package:flutter/...`, `package:flutter_bloc/...`, HTTP clients, or JSON serialization packages.
- `lib/application/`: State management (`Cubit` / `Bloc`) and use-case orchestration.
  - Every state hierarchy MUST be a `sealed class` with `final class` subtypes (`Initial`, `Loading`, `Loaded`, `Error`).
- `lib/main.dart` & `lib/presentation/`: Flutter widgets consuming `Cubit`/`Bloc` states via exhaustive Dart 3 `switch` expressions.
  - Widgets MUST NOT instantiate repositories directly or perform raw I/O inside `build()`.

## 2. Error Handling & Type Safety Invariants
- Never throw raw strings or swallow exceptions with empty `catch (_) {}` blocks.
- All repository methods that can fail MUST return `Future<Result<T>>` (`Success<T>` or `Failure<T>` with `message` and `code`).
- Always use `const` constructors wherever possible and enable `prefer_const_constructors`.

## 3. UI Design Tokens & Accessibility
- Surface Primary: `Color(0xFF070A13)` | Surface Card: `Color(0xFF0F1424)` | Border: `Color(0xFF202B46)`
- Accent Cyan: `Color(0xFF00B0FF)` | Accent Blue: `Color(0xFF02569B)`
- Status Nominal: `Color(0xFF10B981)` | Degraded: `Color(0xFFF59E0B)` | Critical: `Color(0xFFEF4444)`
- Zero gradients: use solid fills and crisp `1px` borders (`Border.all(color: Color(0xFF202B46))`).
- Every interactive `IconButton` or action button MUST include a stable `Key(...)` for deterministic widget testing and a descriptive `tooltip`.

## 4. Mandatory MCP & Verification Workflow
1. Before adding any dependency, query `pub_dev_search` via the Dart MCP server.
2. After creating or modifying any Dart file, run the `analyze_files` MCP tool (or `flutter analyze --fatal-infos`).
3. Never report a task as finished until `flutter analyze --fatal-infos` and `flutter test` pass with 0 warnings and 0 failures.
Step 4 of 8 | Progressive Context Disclosure

Creating On-Demand Procedural Skills (SKILL.md)

A common mistake when adopting AI agents is dumping 3,000 lines of feature templates, database migration guides, release checklists, and widget testing recipes into AGENTS.md. When your root instruction file grows too large, the agent suffers from instruction dilution (attention degradation in the middle of long prompts) and burns unnecessary context tokens on every single chat turn.

The solution is Agent Skills: self-contained folders inside .agents/skills/<skill-name>/SKILL.md. Each skill begins with a compact YAML frontmatter containing only name and description. At startup, the agent reads only the 2-line YAML frontmatter of each skill. When your prompt matches a skill's description (for example, scaffolding a new Clean Architecture feature), the agent dynamically loads the full SKILL.md body into context!

Rule of Thumb: AGENTS.md vs. SKILL.md

Put "What must always be true" (invariants, forbidden imports, verification gates) in AGENTS.md. Put "How to execute a specific workflow step-by-step" (scaffolding a feature, writing FFI bindings, migrating tests) in .agents/skills/<name>/SKILL.md.

Règle d'Or : AGENTS.md vs SKILL.md

Placez "Ce qui doit toujours être vrai" (invariants, imports interdits, portes de validation) dans AGENTS.md. Placez "Comment exécuter une procédure étape par étape" (créer une feature, générer des bindings FFI, écrire des tests) dans .agents/skills/<nom>/SKILL.md.

# Flutter Clean Feature Scaffolding Playbook

Follow these exact steps in order whenever asked to create or update a feature:

## Step 1: Pure Domain Layer (`lib/domain/<feature>.dart`)
1. Define immutable entities with `final` fields, `const` constructors, and `copyWith`.
2. Compute derived domain properties (such as `HealthStatus`) via pure getters on the entity.
3. Define repository contracts as `abstract interface class` returning `Future<Result<T>>`.
4. Verify zero `package:flutter/` imports in this file.

## Step 2: Application State & Cubit (`lib/application/<feature>_cubit.dart`)
1. Declare a `sealed class <Feature>State` with `const` constructor.
2. Create four `final class` subtypes: `Initial`, `Loading`, `Loaded`, and `Error`.
3. In the `Cubit`, emit `Loading`, await the repository's `Result<T>`, and use an exhaustive `switch (result)` with pattern destructuring (`case Success(:final value):`, `case Failure(:final message, :final code):`).

## Step 3: Presentation Layer (`lib/main.dart` or `lib/presentation/`)
1. Inject the `Cubit` via `BlocProvider` and render state via `BlocBuilder`.
2. Use an exhaustive `switch (state)` expression inside `BlocBuilder.builder`.
3. Attach explicit `const Key('...')` identifiers to loading indicators, status badges, and action buttons.

## Step 4: Mandatory Verification
1. Write a `testWidgets` test in `test/<feature>_widget_test.dart` covering both the nominal `Loaded` path and the `Error` recovery path.
2. Call `analyze_files` via the Dart MCP server and run `flutter test`.

Observez comment ce fichier respecte les sections 1 et 2 de AGENTS.md : il ne contient aucun import Flutter ou tiers, définit un type algébrique scellé Result<T>, calcule HealthStatus de façon déterministe et expose un contrat abstract interface class TelemetryRepository :

lib/domain/telemetry_snapshot.dart | Pure Domain Entities & Contracts DART 
// lib/domain/telemetry_snapshot.dart
// Pure Dart domain layer: zero Flutter UI or platform imports allowed.

sealed class Result<T> {
  const Result();
}

final class Success<T> extends Result<T> {
  final T value;
  const Success(this.value);
}

final class Failure<T> extends Result<T> {
  final String message;
  final String code;
  const Failure({required this.message, required this.code});
}

enum HealthStatus { nominal, degraded, critical }

final class TelemetrySnapshot {
  final String nodeId;
  final int latencyMs;
  final double memoryUsageMb;
  final int activeIsolates;
  final DateTime recordedAt;

  const TelemetrySnapshot({
    required this.nodeId,
    required this.latencyMs,
    required this.memoryUsageMb,
    required this.activeIsolates,
    required this.recordedAt,
  });

  HealthStatus get status {
    if (latencyMs >= 500 || memoryUsageMb >= 512.0) {
      return HealthStatus.critical;
    }
    if (latencyMs >= 200 || memoryUsageMb >= 256.0) {
      return HealthStatus.degraded;
    }
    return HealthStatus.nominal;
  }

  TelemetrySnapshot copyWith({
    String? nodeId,
    int? latencyMs,
    double? memoryUsageMb,
    int? activeIsolates,
    DateTime? recordedAt,
  }) {
    return TelemetrySnapshot(
      nodeId: nodeId ?? this.nodeId,
      latencyMs: latencyMs ?? this.latencyMs,
      memoryUsageMb: memoryUsageMb ?? this.memoryUsageMb,
      activeIsolates: activeIsolates ?? this.activeIsolates,
      recordedAt: recordedAt ?? this.recordedAt,
    );
  }
}

abstract interface class TelemetryRepository {
  Future<Result<TelemetrySnapshot>> fetchLatestSnapshot({
    required String nodeId,
  });
}

  const TelemetryLoading();
}

final class TelemetryLoaded extends TelemetryState {
  final TelemetrySnapshot snapshot;
  const TelemetryLoaded(this.snapshot);
}

final class TelemetryError extends TelemetryState {
  final String message;
  final String code;
  const TelemetryError({required this.message, required this.code});
}

class InMemoryTelemetryRepository implements TelemetryRepository {
  bool simulateFailure;
  final Duration latency;

  InMemoryTelemetryRepository({
    this.simulateFailure = false,
    this.latency = const Duration(milliseconds: 120),
  });

  @override
  Future<Result<TelemetrySnapshot>> fetchLatestSnapshot({
    required String nodeId,
  }) async {
    await Future<void>.delayed(latency);
    if (simulateFailure) {
      return const Failure<TelemetrySnapshot>(
        message: 'Telemetry node unreachable over local socket.',
        code: 'ERR_NODE_TIMEOUT',
      );
    }
    return Success<TelemetrySnapshot>(
      TelemetrySnapshot(
        nodeId: nodeId,
        latencyMs: 42,
        memoryUsageMb: 118.4,
        activeIsolates: 3,
        recordedAt: DateTime.utc(2026, 10, 28, 12, 0),
      ),
    );
  }
}

class TelemetryCubit extends Cubit<TelemetryState> {
  final TelemetryRepository _repository;

  TelemetryCubit(this._repository) : super(const TelemetryInitial());

  Future<void> refreshSnapshot({String nodeId = 'edge-node-kampala-01'}) async {
    emit(const TelemetryLoading());
    final result = await _repository.fetchLatestSnapshot(nodeId: nodeId);
    switch (result) {
      case Success<TelemetrySnapshot>(:final value):
        emit(TelemetryLoaded(value));
      case Failure<TelemetrySnapshot>(:final message, :final code):
        emit(TelemetryError(message: message, code: code));
    }
  }
}

tools/architecture_mcp_server.dart | Custom MCP Server with genkit_mcp DART 
// tools/architecture_mcp_server.dart
// Run with: dart run tools/architecture_mcp_server.dart
import 'dart:convert';
import 'dart:io';
import 'package:genkit/genkit.dart';
import 'package:genkit_mcp/genkit_mcp.dart';
import 'package:schemantic/schemantic.dart';

void main() async {
  final ai = Genkit();

  // 1. Expose an MCP Tool that audits lib/domain/ for layer boundary violations
  ai.defineTool(
    name: 'checkLayerImports',
    description:
        'Scans lib/domain/ to verify zero package:flutter, flutter_bloc, or data-layer imports.',
    inputSchema: SchemanticType.map(
      SchemanticType.string(),
      SchemanticType.dynamicSchema(),
    ),
    fn: (input, _) async {
      final domainPath = (input['domainPath'] as String?) ?? 'lib/domain';
      final dir = Directory(domainPath);
      if (!dir.existsSync()) {
        return jsonEncode({
          'status': 'error',
          'message': 'Directory $domainPath does not exist.',
        });
      }

      final violations = <String>[];
      final forbiddenPatterns = [
        'package:flutter/',
        'package:flutter_bloc/',
        '/data/',
        '/presentation/',
      ];

      await for (final entity in dir.list(recursive: true)) {
        if (entity is File && entity.path.endsWith('.dart')) {
          final lines = await entity.readAsLines();
          for (var i = 0; i < lines.length; i++) {
            final line = lines[i].trim();
            if (line.startsWith('import ')) {
              for (final pattern in forbiddenPatterns) {
                if (line.contains(pattern)) {
                  violations.add('${entity.path}:${i + 1} -> $line');
                }
              }
            }
          }
        }
      }

      return jsonEncode({
        'status': violations.isEmpty ? 'passed' : 'failed',
        'checkedDirectory': domainPath,
        'violationCount': violations.length,
        'violations': violations,
      });
    },
  );

  // 2. Expose an MCP Resource serving canonical UI design tokens
  ai.defineResource(
    name: 'design-tokens',
    uri: 'project://design-tokens',
    fn: (_, _) async => ResourceOutput(
      content: [
        TextPart(
          text: jsonEncode({
            'surfacePrimary': '#070A13',
            'surfaceCard': '#0F1424',
            'borderColor': '#202B46',
            'accentCyan': '#00B0FF',
            'accentBlue': '#02569B',
            'statusNominal': '#10B981',
            'statusDegraded': '#F59E0B',
            'statusCritical': '#EF4444',
          }),
        ),
      ],
    ),
  );

  // 3. Start the MCP Server over stdio transport
  final server = createMcpServer(
    ai,
    McpServerOptions(name: 'flutter-arch-guard', version: '1.0.0'),
  );
  await server.start();
}
