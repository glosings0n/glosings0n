Firebase AI Logic vs Genkit Dart vs LiteRT-LM: Hybrid AI Architecture & Smart Routing in Flutter

1. Context & The "Why": The 2026 Flutter AI Architectural Dilemma

In 2026, Flutter engineers building generative AI applications face three distinct execution paradigms across the Google and Dart ecosystem:

  • Client-Side Cloud AI (firebase_ai): Calling gemini-flash-latest directly from Flutter without writing a custom backend, protected by Firebase App Check and Firebase Authentication.
  • Server-Side Agentic AI (genkit Dart): Running structured flows, multi-step tool calling, and privileged business logic on a Dart backend (Shelf / Cloud Run / Cloud Functions).
  • On-Device Edge AI (flutter_edge_ai + LiteRT-LM): Running quantized .litertlm models 100% offline on the user's NPU/GPU/CPU with zero token cost and zero network egress.

Relying on a single paradigm for your entire mobile product creates critical failure modes: a pure-cloud client breaks in rural low-connectivity zones and exposes your API quota if App Check is misconfigured; a pure-edge app cannot execute privileged server transactions or reason over massive cloud indexes; and placing sensitive billing or quota tools inside client code violates core security boundaries.

1. Contexte & Pourquoi : Le dilemme architectural de l'IA sur Flutter en 2026

En 2026, les ingénieurs Flutter concevant des applications d'IA générative disposent de trois paradigmes d'exécution complémentaires au sein de l'écosystème Google et Dart :

  • IA Cloud côté client (firebase_ai) : Appeler gemini-flash-latest directement depuis l'application Flutter sans gérer de serveur dédié, sous la protection de Firebase App Check et Firebase Authentication.
  • IA Agentique côté serveur (genkit Dart) : Exécuter des flux typés (Flows), des appels d'outils (Tool Calling) et des règles métier critiques sur un backend Dart (Shelf / Cloud Run / Cloud Functions).
  • IA Embarquée Edge (flutter_edge_ai + LiteRT-LM) : Exécuter des modèles quantifiés .litertlm 100% hors-ligne sur le NPU/GPU/CPU du téléphone avec un coût de token nul et zéro fuite réseau.

Utiliser un seul paradigme pour l'ensemble d'un produit mobile entraîne des défaillances majeures : une architecture 100% Cloud échoue dès que la connexion 3G/4G tombe et expose vos quotas si App Check est mal configuré ; une architecture 100% Edge ne peut pas valider des transactions serveur privilégiées ; et exécuter des outils de facturation ou de quota côté client viole les invariants de sécurité fondamentaux.

Production Architectural Pattern

Instead of choosing one SDK against the others, high-resilience mobile systems combine all three behind a unified Clean Architecture gateway and route each prompt dynamically based on connectivity, data sensitivity (PII), and transactional authority.

Plutôt que d'opposer ces trois SDK, les systèmes mobiles résilients les unifient derrière une passerelle Clean Architecture unique et routent chaque requête dynamiquement selon la connectivité, la sensibilité des données (PII) et l'autorité transactionnelle requise.

The Absolute Server-Side Security Invariant

A common anti-pattern in mobile AI apps is giving a client-side LLM tool-calling access to mutate Firestore documents directly (such as incrementing user credits, approving identity verification, or unlocking paid tiers). Even with Firebase App Check enabled, the client binary runs on untrusted hardware.

  • Rule 1 (Never Trust Client Decisions on Value): The mobile client (whether executing firebase_ai or local LiteRT-LM) must never decide subscription quotas, payment settlements, verification badges, or cross-tenant data access.
  • Rule 2 (Server Authority via Genkit Dart): Any AI workflow that triggers a state mutation with commercial, financial, or security impact must execute inside a Genkit Dart Flow on your backend, authenticating the caller's Firebase ID Token and enforcing atomic database transactions server-side.
  • Rule 3 (Zero-Egress Privacy on Edge): Conversely, when a user drafts private personal notes, medical symptoms, or confidential field logs, routing that prompt to LiteRT-LM guarantees mathematically that raw PII never leaves the physical handset.

L'Invariant Absolu de Sécurité Côté Serveur

Une erreur d'architecture fréquente dans les applications mobiles IA consiste à autoriser un modèle côté client à modifier directement des documents critiques en base de données (comme créditer un quota, valider un statut de vérification ou débloquer un abonnement). Même avec Firebase App Check activé, le binaire client s'exécute sur un matériel non fiable.

  • Règle 1 (Zéro autorité client sur la valeur métier) : Le client mobile (qu'il utilise firebase_ai ou LiteRT-LM en local) ne doit jamais décider des quotas d'abonnement, des règlements financiers, des statuts certifiés ou des accès inter-utilisateurs.
  • Règle 2 (Autorité Serveur via Genkit Dart) : Tout workflow IA déclenchant une mutation d'état à valeur commerciale ou sécuritaire doit s'exécuter dans un Flow Genkit Dart côté serveur, après vérification du jeton d'identité Firebase (ID Token) et application atomique des règles métier.
  • Règle 3 (Confidentialité sans sortie réseau sur l'Edge) : À l'inverse, lorsqu'un utilisateur traite des notes personnelles sensibles, des données médicales ou des relevés confidentiels sur le terrain, le routage vers LiteRT-LM garantit qu'aucune donnée privée (PII) ne quitte le téléphone.
Why Firebase App Check Is Mandatory for Tier 1 (firebase_ai)

While firebase_ai keeps your Gemini API key off the client device by proxying requests through the Firebase AI Logic backend, an unprotected Firebase project ID can still be abused by extracted client configs. Always activate Firebase App Check (Play Integrity on Android, DeviceCheck / App Attest on iOS) so only genuine, untampered instances of your app can consume your Gemini quota.

Bien que firebase_ai évite d'embarquer votre clé API Gemini dans l'APK en passant par le proxy Firebase AI Logic, un identifiant de projet Firebase non protégé reste vulnérable aux abus de quota. Activez systématiquement Firebase App Check (Play Integrity sur Android, DeviceCheck / App Attest sur iOS) afin que seules les instances authentiques et non altérées de votre application puissent consommer votre quota Gemini.

// lib/data/firebase_ai_cloud_engine.dart
import 'dart:async';
import '../domain/ai_models.dart';

/// Signature for invoking `FirebaseAI.googleAI().generativeModel(...)`.
typedef CloudPromptInvoker = Future<String> Function(
  String modelName,
  String systemInstruction,
  String userPrompt,
);

/// Tier 1 Engine: Client-Side Cloud Inference via Firebase AI Logic.
///
/// Production wiring with `package:firebase_ai/firebase_ai.dart`:
/// ```dart
/// await FirebaseAppCheck.instance.activate(
///   androidProvider: AndroidProvider.playIntegrity,
///   appleProvider: AppleProvider.appAttest,
/// );
/// final googleAI = FirebaseAI.googleAI(auth: FirebaseAuth.instance);
/// final model = googleAI.generativeModel(
///   model: 'gemini-flash-latest',
///   systemInstruction: Content.system(systemInstruction),
/// );
/// final res = await model.generateContent([Content.text(userPrompt)]);
/// return res.text ?? '';
/// ```
class FirebaseAiCloudEngine implements AiEngineGateway {
  FirebaseAiCloudEngine({
    CloudPromptInvoker? invoker,
    this.modelName = 'gemini-flash-latest',
    this.timeout = const Duration(seconds: 12),
  }) : _invoker = invoker ?? _defaultSimulatedCloudInvoker;

  final CloudPromptInvoker _invoker;
  final String modelName;
  final Duration timeout;

  static const String _systemPrompt =
      'You are a concise engineering assistant accessed via Firebase AI Logic. '
      'Never claim authority to mutate billing quotas or database roles directly.';

  @override
  AiExecutionTier get tier => AiExecutionTier.cloudFirebaseAi;

  @override
  Future<String> generate({
    required String prompt,
    Map<String, Object?> metadata = const {},
  }) async {
    final trimmed = prompt.trim();
    if (trimmed.isEmpty) {
      throw ArgumentError('Prompt cannot be empty for Firebase AI Logic.');
    }

    final responseText = await _invoker(
      modelName,
      _systemPrompt,
      trimmed,
    ).timeout(timeout);

    if (responseText.trim().isEmpty) {
      throw StateError('Firebase AI Logic ($modelName) returned an empty text payload.');
    }
    return responseText.trim();
  }

  static Future<String> _defaultSimulatedCloudInvoker(
    String model,
    String systemInstruction,
    String prompt,
  ) async {
    await Future<void>.delayed(const Duration(milliseconds: 320));
    return '[Firebase AI Logic | $model] Processed multimodal/cloud prompt '
        'with App Check attestation verified: "$prompt"';
  }
}

import 'package:genkit/genkit.dart';
import 'package:genkit_google_genai/genkit_google_genai.dart';
import 'package:schemantic/schemantic.dart';

void configureServerFlows() {
  final ai = Genkit(plugins: [googleAI()]);

  // Privileged server-only tool: never exposed to direct client manipulation.
  ai.defineTool(
    name: 'verifyAndAllocateOrganizationQuota',
    description: 'Verifies billing ledger state and allocates monthly AI compute quota.',
    inputSchema: SchemanticType.map(.string(), .string()),
    fn: (input, _) async {

import 'dart:async';
import 'dart:convert';
import 'package:http/http.dart' as http;
import '../domain/ai_models.dart';

/// Tier 2 Engine: Server-Side Agentic Workflows via Genkit Dart Remote Actions.
///
/// Enforces the Absolute Server-Side Security Invariant:
/// Any operation touching user quotas, payment ledgers, or privileged tools
/// executes exclusively on the Dart backend after verifying the Firebase ID Token.
class GenkitServerEngine implements AiEngineGateway {
  GenkitServerEngine({
    required this.flowEndpoint,
    required this.idTokenProvider,
    http.Client? httpClient,
    this.timeout = const Duration(seconds: 15),
  }) : _httpClient = httpClient;

  final Uri flowEndpoint;
  final Future<String> Function() idTokenProvider;
  final http.Client? _httpClient;
  final Duration timeout;

  @override
  AiExecutionTier get tier => AiExecutionTier.serverGenkitAgent;

  @override
  Future<String> generate({
    required String prompt,
    Map<String, Object?> metadata = const {},
  }) async {
    final idToken = await idTokenProvider();
    if (idToken.isEmpty) {
      throw StateError('Unauthenticated client: missing Firebase Auth ID token.');
    }

    // If no live HTTP client is injected, run deterministic local verification
    // of the Genkit Flow JSON envelope contract.
    if (_httpClient == null) {
      await Future<void>.delayed(const Duration(milliseconds: 410));
      return '[Genkit Dart Server | gemini-2.5-flash] Server-side security '
          'invariant verified (Bearer token + quota ledger check passed). '
          'Executed privileged workflow for: "${prompt.trim()}"';
    }

    final response = await _httpClient
        .post(
          flowEndpoint,
          headers: <String, String>{
            'Content-Type': 'application/json',
            'Authorization': 'Bearer $idToken',
          },
          body: jsonEncode(<String, Object?>{
            'data': <String, Object?>{
              'prompt': prompt.trim(),
              'metadata': metadata,
            },
          }),
        )
        .timeout(timeout);

    if (response.statusCode != 200) {
      throw StateError(
        'Genkit flow failed with HTTP ${response.statusCode}: ${response.body}',
      );
    }

    final decoded = jsonDecode(response.body) as Map<String, Object?>;
    final result = decoded['result']?.toString() ?? '';
    if (result.isEmpty) {
      throw StateError('Genkit flow returned an empty result field.');
    }
    return result;
  }
}

Tier 3 | 100% Offline Edge Inference with flutter_edge_ai & LiteRT-LM

What happens when your user enters an elevator, travels into a rural agricultural zone with zero cellular coverage, or types a strictly private note containing sensitive PII? Our third tier, LiteRT-LM via flutter_edge_ai (formerly flutter_gemma), executes a 4-bit quantized Gemma, Phi, or Qwen model directly on the device's NPU/GPU/CPU.

Three Production Guardrails for On-Device LiteRT-LM

  1. Strict FFI Mutex Serialization: The underlying C++ LiteRT-LM / MediaPipe session is not thread-safe for concurrent prompt streams. Always serialize access with a Dart Completer<void> lock.
  2. Deadlock Timeout Recovery: If a developer triggers a Flutter Hot Restart while a native C++ inference is in flight, a naive mutex would block forever. Always attach a timeout (e.g., 25 seconds) that resets the lock cleanly.
  3. Low-RAM Deterministic Guard (< 2GB Available RAM): Before allocating native KV-cache tensors on budget devices, inspect available memory and fall back to a zero-RAM deterministic ruleset if the OS is under extreme memory pressure.

  1. Sérialisation stricte par Mutex FFI : La session native C++ LiteRT-LM / MediaPipe ne supporte pas deux flux d'inférence simultanés. Sérialisez systématiquement les appels avec un verrou Dart Completer<void>.
  2. Récupération anti-deadlock par Timeout : Si un Hot Restart survient pendant une inférence C++ native, un mutex classique bloquerait l'application indéfiniment. Ajoutez toujours un délai d'expiration (ex. 25 secondes) pour libérer le verrou proprement.
  3. Garde-fou déterministe Basse-RAM (< 2 Go de RAM libre) : Sur les téléphones d'entrée de gamme soumis à une forte pression mémoire, vérifiez la RAM disponible avant d'allouer le cache KV natif et basculez vers un moteur de règles local sans surcoût mémoire.

// lib/data/litert_edge_engine.dart
import 'dart:async';
import '../domain/ai_models.dart';

/// Signature for invoking the native C++ LiteRT-LM session via `flutter_edge_ai`.
typedef LiteRtNativeInvoker = Future<String> Function(String prompt);

/// Tier 3 Engine: 100% Offline On-Device Inference via LiteRT-LM (`flutter_edge_ai`).
///
/// Guarantees:
/// 1. Strict mutex serialization so two concurrent UI requests never collide
///    inside the native C++ MediaPipe / LiteRT-LM session.
/// 2. Deadlock recovery timeout so a stalled native session releases the lock.
/// 3. Zero-RAM deterministic fallback on ultra-low-memory devices (<2GB RAM).
class LiteRtEdgeEngine implements AiEngineGateway {
  LiteRtEdgeEngine({
    LiteRtNativeInvoker? nativeInvoker,
    this.lockTimeout = const Duration(seconds: 25),
  }) : _nativeInvoker = nativeInvoker ?? _defaultSimulatedLiteRtInvoker;

  final LiteRtNativeInvoker _nativeInvoker;
  final Duration lockTimeout;
  Completer<void>? _activeLock;

  @override
  AiExecutionTier get tier => AiExecutionTier.edgeLiteRt;

  @override
  Future<String> generate({
    required String prompt,
    Map<String, Object?> metadata = const {},
  }) async {
    final availableRamMb = (metadata['availableRamMb'] as int?) ?? 4096;
    if (availableRamMb < 2048) {
      return _deterministicLowRamFallback(prompt);
    }

    return _runLocked<String>(() async {
      final formattedPrompt =
          '<start_of_turn>user\n${prompt.trim()}<end_of_turn>\n'
          '<start_of_turn>model\n';
      return _nativeInvoker(formattedPrompt);
    });
  }

  Future<T> _runLocked<T>(Future<T> Function() action) async {
    while (_activeLock != null) {
      try {
        await _activeLock!.future.timeout(lockTimeout);
      } on TimeoutException {
        // Recover from a stalled FFI session after Hot Restart or native hang.
        _activeLock = null;
        break;
      }
    }

    final completer = Completer<void>();
    _activeLock = completer;

    try {
      return await action();
    } finally {
      _activeLock = null;
      if (!completer.isCompleted) {
        completer.complete();
      }
    }
  }

  String _deterministicLowRamFallback(String prompt) {
    return '[LiteRT-LM Safe Mode | <2GB RAM Guard] Device memory is critically '
        'low. Returning deterministic local ruleset summary for: "${prompt.trim()}"';
  }

  static Future<String> _defaultSimulatedLiteRtInvoker(
    String formattedPrompt,
  ) async {
    await Future<void>.delayed(const Duration(milliseconds: 190));
    final clean = formattedPrompt
        .replaceAll('<start_of_turn>user\n', '')
        .replaceAll('<end_of_turn>\n<start_of_turn>model\n', '');
    return '[LiteRT-LM On-Device | gemma-3n-E2B-it-int4] 100% offline inference '
        '(0 bytes network egress, \$0.00 token cost): "$clean"';
  }
}

lib/application/smart_hybrid_ai_router.dart | 5-Rule Hybrid Router + Auto Fallback DART 
// lib/application/smart_hybrid_ai_router.dart
import '../domain/ai_models.dart';

/// Evaluates runtime constraints (connectivity, PII sensitivity, server authority,
/// and hardware limits) to dispatch requests across Cloud, Server, and Edge AI.
class SmartHybridAiRouter {
  const SmartHybridAiRouter({
    required AiEngineGateway cloudEngine,
    required AiEngineGateway serverEngine,
    required AiEngineGateway edgeEngine,
  })  : _cloudEngine = cloudEngine,
        _serverEngine = serverEngine,
        _edgeEngine = edgeEngine;

  final AiEngineGateway _cloudEngine;
  final AiEngineGateway _serverEngine;
  final AiEngineGateway _edgeEngine;

  /// Selects the target tier and reason before executing inference.
  (AiEngineGateway, String) selectTargetEngine(RoutingContext context) {
    // Rule 1: Strict PII or confidential local notes NEVER leave the device.
    if (context.sensitivity == TaskSensitivity.strictLocalPii) {
      return (
        _edgeEngine,
        'Strict PII policy: zero network egress enforced via on-device LiteRT-LM.',
      );
    }

    // Rule 2: Privileged tools, billing quotas, or state mutations require Server authority.
    if (context.requiresPrivilegedServerTool ||
        context.sensitivity == TaskSensitivity.privilegedTransactional) {
      if (!context.isOnline) {
        return (
          _edgeEngine,
          'Offline during privileged request: queued transaction & serving local LiteRT-LM guidance.',
        );
      }
      return (
        _serverEngine,
        'Server-Side Security Invariant: routed to Genkit Dart backend for privileged tool execution.',
      );
    }

    // Rule 3: Offline mode routes immediately to on-device LiteRT-LM.
    if (!context.isOnline) {
      return (
        _edgeEngine,
        'Device is offline: routed to local LiteRT-LM INT4 engine (\$0.00 token cost).',
      );
    }

    // Rule 4: Online + Multimodal attachment -> Firebase AI Logic.
    if (context.hasMultimodalAttachment) {
      return (
        _cloudEngine,
        'Online multimodal input: routed to Firebase AI Logic (gemini-flash-latest + App Check).',
      );
    }

    // Rule 5: Short, routine prompts on capable devices (>=4GB RAM) run locally to save cloud quota.
    if (context.prompt.length < 160 && context.availableRamMb >= 4096) {
      return (
        _edgeEngine,
        'Cost optimization: short prompt on 4GB+ RAM device offloaded to local LiteRT-LM.',
      );
    }

    return (
      _cloudEngine,
      'Online complex synthesis: routed to Firebase AI Logic (gemini-flash-latest).',
    );
  }

  /// Dispatches the prompt and automatically falls back to LiteRT-LM on network failure.
  Future<AiInferenceResponse> routeAndExecute(RoutingContext context) async {
    final stopwatch = Stopwatch()..start();
    final (primaryEngine, reason) = selectTargetEngine(context);

    try {
      final output = await primaryEngine.generate(
        prompt: context.prompt,
        metadata: <String, Object?>{
          'availableRamMb': context.availableRamMb,
          'hasMultimodalAttachment': context.hasMultimodalAttachment,
        },
      );
      stopwatch.stop();

      return AiInferenceResponse(
        text: output,
        telemetry: RoutingTelemetry(
          selectedTier: primaryEngine.tier,
          routingReason: reason,
          latencyMs: stopwatch.elapsedMilliseconds,
        ),
      );
    } catch (cloudOrServerError) {
      // If the primary engine was Cloud or Server and failed due to flaky network,
      // transparently fall back to on-device LiteRT-LM so UX never breaks.
      if (primaryEngine.tier != AiExecutionTier.edgeLiteRt) {
        final fallbackOutput = await _edgeEngine.generate(
          prompt: context.prompt,
          metadata: <String, Object?>{
            'availableRamMb': context.availableRamMb,
          },
        );
        stopwatch.stop();

        return AiInferenceResponse(
          text: fallbackOutput,
          telemetry: RoutingTelemetry(
            selectedTier: AiExecutionTier.edgeLiteRt,
            routingReason:
                'Automatic Edge Fallback after ${primaryEngine.tier.label} error: $cloudOrServerError',
            latencyMs: stopwatch.elapsedMilliseconds,
            didFallbackToEdge: true,
          ),
        );
      }
      rethrow;
    }
  }
}

        prompt: 'Analyze this detailed multi-paragraph architectural specification '
            'and compare all latency trade-offs across regions and mobile carriers '
            'with full token budget breakdowns for 10,000 daily active users.',
        isOnline: true,
      ),
    );

    expect(res.telemetry.selectedTier, equals(AiExecutionTier.edgeLiteRt));
    expect(res.telemetry.didFallbackToEdge, isTrue);
  });

2. Key Engineering Takeaways

  1. Provision Before Coding: Always run npx firebase-tools@latest init ailogic before calling firebase_ai; flutterfire configure alone does not enable the backend proxy.
  2. Protect Client Quotas with App Check: Never ship firebase_ai to production without activating FirebaseAppCheck (Play Integrity on Android and App Attest on iOS).
  3. Enforce Server-Side Security Invariants: Any tool that mutates financial balances, subscription quotas, or security roles belongs exclusively inside a Genkit Dart Flow on a trusted server.
  4. Guarantee Continuity with LiteRT-LM Fallback: Wrapping cloud and server engines with an automatic fallback to a mutex-protected LiteRT-LM engine ensures your users never hit a dead screen when offline.

2. Points Clés à Retenir

  1. Provisionner avant de coder : Exécutez toujours npx firebase-tools@latest init ailogic avant d'appeler firebase_ai ; flutterfire configure seul n'active pas le proxy backend.
  2. Protéger les quotas clients avec App Check : Ne déployez jamais firebase_ai en production sans activer FirebaseAppCheck (Play Integrity sur Android et App Attest sur iOS).
  3. Appliquer les invariants de sécurité côté serveur : Tout outil modifiant des soldes financiers, des quotas d'abonnement ou des rôles de sécurité doit résider exclusivement dans un Flow Genkit Dart sur un serveur de confiance.
  4. Garantir la continuité grâce au repli LiteRT-LM : Encapsuler les moteurs Cloud et Serveur avec une bascule automatique vers un moteur LiteRT-LM protégé par mutex garantit une expérience sans interruption hors-ligne.
