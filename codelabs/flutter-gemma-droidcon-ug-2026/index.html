Step 3 of 9 • Memory & Distribution

Model Quantization (INT4 vs. INT8) & Atomic Asset Delivery

On a mid-tier 4GB RAM Android phone, Android OS and system services consume ~1.6GB of RAM, and the Flutter UI + Dart VM take ~300MB. That leaves a strict ceiling of ~1.8GB to 2.0GB before Android's Low Memory Killer (lmkd) terminates your app.

~4.0 GB 2B Model in FP16 (Crashes on 4GB RAM)
~2.1 GB 2B Model in INT8 (Zero headroom for Vision)
~1.2 GB E2B in INT4 .litertlm (75% smaller!)
134 MB Distilled 240M SLM in INT4 (See Step 8)
Production Pitfall: Never Put Multi-Hundred-MB Models in Flutter assets/

Bundling a 1.3GB model inside pubspec.yaml assets violates Google Play's 150MB base APK/AAB limit and forces Flutter to copy/decompress the asset on first boot—causing instant OutOfMemoryError crashes on budget phones.

The Solution: Chunked Streaming + Atomic .tmp Swap

In lib/data/repositories/chat_repository_impl.dart, we stream the quantized .litertlm binary directly to getApplicationDocumentsDirectory() using an IOSink (so Dart's RAM heap stays flat at <5MB). Crucially, we write to gemma.litertlm.tmp first and only rename it to gemma.litertlm when 100% of bytes are on disk. If a user's connection drops at 89%, the native C++ engine will never attempt to memory-map a corrupted binary!

lib/data/repositories/chat_repository_impl.dart DART 
@override
Future<bool> checkModelInstalled() async {
  final directory = await getApplicationDocumentsDirectory();
  final litertlmFile = File('${directory.path}/gemma.litertlm');
  final binFile = File('${directory.path}/gemma.bin');

  // Auto-migrate legacy gemma.bin to gemma.litertlm if already on the user's phone
  if (await binFile.exists() && !await litertlmFile.exists()) {
    await binFile.rename(litertlmFile.path);
  }
  return await litertlmFile.exists();
}

@override
Future<void> initializeGemma(Function(double) onProgress) async {
  return GemmaEngineManager.runWithLock(() async {
    await GemmaEngineManager.ensureInitialized();

    final directory = await getApplicationDocumentsDirectory();
    final modelFile = File('${directory.path}/gemma.litertlm');
    final tempModelFile = File('${directory.path}/gemma.litertlm.tmp');

    if (!await modelFile.exists()) {
      // 1. Clean up any incomplete .tmp file from an interrupted download
      if (await tempModelFile.exists()) {
        await tempModelFile.delete();
      }

      // 2. Fast 4-second DNS check before opening the download stream
      final result = await InternetAddress.lookup('google.com')
          .timeout(const Duration(seconds: 4));
      if (result.isEmpty || result.first.rawAddress.isEmpty) {
        throw const SocketException('Internet connection is required for first-time setup.');
      }

      const url = 'https://huggingface.co/litert-community/'
          'gemma-4-E2B-it-litert-lm/resolve/main/gemma-4-E2B-it.litertlm';
      final client = http.Client();

      try {
        final request = http.Request('GET', Uri.parse(url));
        final response = await client.send(request);
        if (response.statusCode != 200) {
          throw HttpException('Download failed (HTTP ${response.statusCode})');
        }

        final contentLength = response.contentLength ?? 0;
        int downloadedBytes = 0;

        // 3. Stream chunks directly to disk via IOSink (Zero RAM bloat)
        final IOSink sink = tempModelFile.openWrite();
        await response.stream.forEach((chunk) {
          downloadedBytes += chunk.length;
          sink.add(chunk);
          if (contentLength > 0) {
            onProgress(downloadedBytes / contentLength);
          }
        });
        await sink.close();

        // 4. ATOMIC RENAME: Only promote to gemma.litertlm upon 100% completion
        if (await tempModelFile.exists()) {
          await tempModelFile.rename(modelFile.path);
        }
      } catch (e) {
        if (await tempModelFile.exists()) await tempModelFile.delete();
        rethrow;
      } finally {
        client.close();
      }
    }

    // 5. Register the verified local file with FlutterGemma's LiteRT-LM runtime
    await FlutterGemma.installModel(
      modelType: ModelType.gemmaIt,
      fileType: ModelFileType.litertlm,
    ).fromFile(modelFile.path).install();
  });
}
Step 4 of 9 • Native Concurrency

Preventing Native FFI Crashes & Hot-Reload Deadlocks

What Failed in Production #1: Concurrent Native Sessions & Orphaned Isolates

MediaPipe / LiteRT-LM allocates a single native C++ execution graph in memory. During field testing, if a user started a leaf scan and switched to the Chat tab before the scan finished—or if a developer triggered a Flutter Hot Reload while a stream was open—the native FFI channel deadlocked permanently or threw PlatformException(channel-error).

The Solution: GemmaEngineManager

To make on-device inference rock-solid, we built GemmaEngineManager in lib/core/services/gemma_engine_manager.dart. It serializes all Future and Stream operations through a Completer mutex lock, includes an 8-second deadlock timeout to recover from orphaned Hot-Reload isolates, and automatically resets stale chat session pointers when a native channel error occurs:

lib/core/services/gemma_engine_manager.dart DART 
import 'dart:async';
import 'dart:developer' as dev;
import 'package:flutter_gemma/flutter_gemma.dart';
import 'package:flutter_gemma_litertlm/flutter_gemma_litertlm.dart';

class GemmaEngineManager {
  static bool _isInitialized = false;
  static Completer<void>? _initCompleter;
  static Future<void>? _activeExecution;
  static Function()? _onResetChatCallback;

  static bool get isInitialized => _isInitialized;
  static bool get isBusy => _activeExecution != null;

  static void setResetChatCallback(Function() callback) {
    _onResetChatCallback = callback;
  }

  static void resetChatSession() {
    _onResetChatCallback?.call();
  }

  /// Force clears stale lock state and resets chat session on Hot Reload or FFI error
  static void forceResetLockState() {
    dev.log("Force resetting GemmaEngineManager lock state & session handles.");
    _activeExecution = null;
    _initCompleter = null;
    resetChatSession();
  }

  static Future<void> ensureInitialized() async {
    if (_isInitialized) return;
    if (_initCompleter != null) return _initCompleter!.future;

    _initCompleter = Completer<void>();
    try {
      await FlutterGemma.initialize(
        inferenceEngines: const [LiteRtLmEngine()],
      );
      _isInitialized = true;
      _initCompleter!.complete();
    } catch (e) {
      // Native FFI engine already bound across Hot Reload
      _isInitialized = true;
      if (!(_initCompleter?.isCompleted ?? true)) _initCompleter!.complete();
    } finally {
      _initCompleter = null;
    }
  }

  /// Wraps a Future operation to guarantee single-threaded execution on LiteRT-LM
  static Future<T> runWithLock<T>(Future<T> Function() action) async {
    final previousExecution = _activeExecution;
    final completer = Completer<void>();
    _activeExecution = completer.future;

    if (previousExecution != null) {
      try {
        await previousExecution.timeout(const Duration(seconds: 8));
      } on TimeoutException {
        forceResetLockState();
      } catch (_) {}
    }

    try {
      return await action();
    } catch (e) {
      if (e.toString().contains("channel-error") ||
          e.toString().contains("PlatformException") ||
          e.toString().contains("Null")) {
        forceResetLockState();
      }
      rethrow;
    } finally {
      completer.complete();
      if (_activeExecution == completer.future) _activeExecution = null;
    }
  }

  /// Wraps a Stream operation with the same FFI mutex & deadlock protection
  static Stream<T> runStreamWithLock<T>(Stream<T> Function() streamFactory) async* {
    final previousExecution = _activeExecution;
    final completer = Completer<void>();
    _activeExecution = completer.future;

    if (previousExecution != null) {
      try {
        await previousExecution.timeout(const Duration(seconds: 8));
      } on TimeoutException {
        forceResetLockState();
      } catch (_) {}
    }

    try {
      await for (final value in streamFactory()) {
        yield value;
      }
    } catch (e) {
      if (e.toString().contains("channel-error") ||
          e.toString().contains("PlatformException")) {
        forceResetLockState();
      }
      rethrow;
    } finally {
      completer.complete();
      if (_activeExecution == completer.future) _activeExecution = null;
    }
  }
}
Step 5 of 9 • Multimodal Vision

512px Image Optimization & Prompt-Level Early-Exit Guardrails

What Failed in Production #2 & #3: 12MP Camera OOMs & CPU Thermal Throttling

1. Vision OOMs: Passing a raw 4000×3000 (12MP) camera image into Message.withImage() allocates a 48MB RGBA buffer plus huge vision encoder tensors—crashing 4GB RAM phones.
2. Wasted Compute on Non-Leaves: When a farmer accidentally photographed their shoe, face, or tool, Gemma generated 800+ tokens of hallucinated plant advice, heating up the CPU and draining battery.

1. Downsample Camera Images to 512px & Dispose Native Handles

Gemma's vision encoder downscales inputs internally anyway. By resizing the image to targetWidth: 512 in Dart's dart:ui codec and calling image.dispose() immediately before invoking LiteRT-LM, we cut vision memory consumption by 85% and speed up vision encoding by 4x.

2. Two-Stage Prompt with Immediate Early-Exit Short-Circuit

Below is the complete implementation from lib/data/datasources/gemma_local_source.dart (with the prompt translated to English for this workshop). Notice how Step 1 of the prompt forces Gemma to output a single 18-token rejection sentence and halt immediately if the image is not a plant leaf:

lib/data/datasources/gemma_local_source.dart DART 
import 'dart:io';
import 'dart:typed_data';
import 'dart:ui' as ui;
import 'package:flutter_gemma/flutter_gemma.dart';
import 'package:gemmea/core/services/gemma_engine_manager.dart';
import 'package:gemmea/core/utils/text_sanitizer.dart';
import 'package:gemmea/data/datasources/sqlite_helper.dart';

class GemmaLocalSourceImpl {
  Future<String> evaluateCropImage(File imageFile, String prompt) async {
    return GemmaEngineManager.runWithLock(() async {
      GemmaEngineManager.resetChatSession();
      try {
        await GemmaEngineManager.ensureInitialized();
        final rawBytes = await imageFile.readAsBytes();

        // 1. Downsample to 512px max width to prevent native OOM crashes
        final imageBytes = await _optimizeImageBytes(rawBytes);

        // 2. Fetch grounded FAO/IITA context from local SQLite FTS5
        final faoContext = await _fetchRagContextFromSqlite(imageFile.path, prompt);

        // 3. Prefer CPU backend on budget devices whose GPUs lack OpenCL vision buffers
        InferenceModel model;
        try {
          model = await FlutterGemma.getActiveModel(
            supportImage: true,
            maxTokens: 4096,
            preferredBackend: PreferredBackend.cpu,
          );
        } catch (_) {
          model = await FlutterGemma.getActiveModel(
            supportImage: true,
            maxTokens: 4096,
          );
        }

        final session = await model.createSession();

        // 4. Multimodal VLM Prompt with Step 1 Early-Exit Short-Circuit (in English)
        final vlmPrompt = '''
You are Gemmea, the offline AI agronomist for crop health diagnosis in East Africa.
Examine the provided image carefully.

ABSOLUTE AND URGENT RULE (IMMEDIATE EVALUATION):
Step 1: Look at the image. If it is NOT a plant leaf or agricultural crop
(e.g., human face, phone, shoe, furniture, animal, non-plant object):
Immediately STOP all generation and reply ONLY with this exact sentence:
"The captured image does not appear to be a plant leaf. Please retake a photo clearly targeting a leaf from your crop."
DO NOT GENERATE ANY HEADINGS AND DO NOT USE THE RAG CONTEXT BELOW.

Step 2: IF AND ONLY IF THE IMAGE IS GENUINELY A PLANT LEAF OR CROP:
Provide a detailed, structured agronomic analysis organized into these 7 sections (NO EMOJIS):

### 1. PRIMARY DIAGNOSIS & HYPOTHESES
- Crop: [Exact crop observed: Maize, Cassava, Bean, Banana, Tomato, Coffee, or Unknown]
- Disease: [If healthy, write EXPLICITLY: "No disease (Healthy Leaf)". If diseased, state exact pathogen/disease name]
- Confidence Level: [e.g., 90%]
- Differential Diagnoses: [Environmental or secondary factors if applicable]
### 2. DETAILED OBSERVED SYMPTOMS
(Chlorosis, pustules, mosaic patterns, curling, necrotic streaks, or intact lamina).
### 3. CAUSES & VECTORS (IITA STANDARDS)
(Pathogen agent and transmission vector such as Bemisia tabaci whitefly or Xanthomonas).
### 4. STEP-BY-STEP ORGANIC REMEDIES & TREATMENT
(Local bio-remedies: Neem leaf extract 200g/L, wood ash, baking soda NaHCO3 5g/L with black soap, Tithonia liquid manure).
### 5. SOIL MANAGEMENT, NUTRIENTS & IRRIGATION
(Drainage, composting, mulching, moisture control).
### 6. IMMEDIATE 3-STEP ACTION PLAN
(Step 1, Step 2, Step 3 for the farmer today).
### 7. OFFICIAL FAO & IITA REFERENCES
(Explicit citations from the local RAG context below).

REFERENCE RAG CONTEXT (IGNORE COMPLETELY IF NOT A PLANT):
$faoContext

User instruction: $prompt
''';

        await session.addQueryChunk(
          Message.withImage(
            text: vlmPrompt,
            imageBytes: imageBytes,
            isUser: true,
          ),
        );

        final String response = await session.getResponse();
        return TextSanitizer.cleanLatexAndFormatting(response);
      } finally {
        GemmaEngineManager.resetChatSession();
      }
    });
  }

  Future<Uint8List> _optimizeImageBytes(Uint8List inputBytes) async {
    try {
      final codec = await ui.instantiateImageCodec(
        inputBytes,
        targetWidth: 512,
      );
      final frameInfo = await codec.getNextFrame();
      final image = frameInfo.image;
      final byteData = await image.toByteData(format: ui.ImageByteFormat.png);
      image.dispose(); // Crucial: release native C++ Skia/Impeller texture immediately!
      if (byteData != null) {
        return byteData.buffer.asUint8List();
      }
    } catch (_) {}
    return inputBytes;
  }
}
Step 6 of 9 • Grounded Local Retrieval

Zero-RAM-Overhead Local RAG with SQLite FTS5 & BM25

Quantized 2B models can hallucinate exact biopesticide dosages or regional planting dates if left ungrounded. However, on a 4GB RAM phone where Gemma is already consuming ~1.3GB of RAM, loading a second neural embedding model + vector database into RAM will push your app over the OOM cliff.

Architectural Win: SQLite FTS5 + BM25 Ranking = 0 MB Extra RAM

SQLite's built-in FTS5 (Full-Text Search 5) engine executes in native C directly on disk using the BM25 relevance algorithm. It requires 0 MB of neural embedding RAM, completes searches in <2 milliseconds, and includes a multi-term weighted scorer fallback for custom Android OEM ROMs.

    'source_citation': 'FAO/IITA Great Lakes Banana Emergency Bulletin (2024), p. 12',
  });
}

/// Searches the local FAO/IITA knowledge base using FTS5 BM25 with scored fallback
Future<List<Map<String, dynamic>>> searchFAOKnowledge(String query) async {
  final db = await database;
  final normalized = _stripAccents(query.toLowerCase())
      .replaceAll(RegExp(r'[^a-z0-9\s]'), ' ');
  final terms = normalized
      .split(RegExp(r'\s+'))
      .where((t) => t.length > 2 && !_stopWords.contains(t))
      .toList();

  if (terms.isEmpty) {
    return await db.query('fao_knowledge_base', limit: 3);
  }

  // Primary Path: Native C FTS5 MATCH ordered by BM25 relevance score
  try {
    final ftsQuery = terms.map((t) => '"$t*"').join(' OR ');
    final ftsResults = await db.rawQuery('''
      SELECT k.* FROM fao_knowledge_base k
      JOIN fao_knowledge_fts fts ON k.id = fts.rowid
      WHERE fao_knowledge_fts MATCH ?
      ORDER BY bm25(fao_knowledge_fts) ASC
      LIMIT 3
    ''', [ftsQuery]);

    if (ftsResults.isNotEmpty) return ftsResults;
  } catch (_) {
    // Fallback to weighted field scoring if OEM SQLite lacks FTS5 module
  }

  return await _scoredFallbackSearch(db, terms);
}

3. Clean Raw LaTeX & Emoji Tokens with TextSanitizer

Create lib/core/utils/text_sanitizer.dart so chemical formulas like $NaHCO_3$ are converted into clean plain text while streaming:

lib/core/utils/text_sanitizer.dart DART 
class TextSanitizer {
  static String cleanLatexAndFormatting(String input, {bool preserveWhitespace = false}) {
    if (input.isEmpty) return input;
    String text = input;

    // Convert common LaTeX chemical formulas to farmer-friendly plain text
    text = text.replaceAll(
      RegExp(r'\$?\\?text\{NaHCO\}_?\{?3\}?\\?\$?|\$NaHCO_3\\?\$?', caseSensitive: false),
      'Baking soda (NaHCO3)',
    );
    text = text.replaceAllMapped(
      RegExp(r'([A-Za-z]+)_\{?(\d+)\}?'),
      (m) => '${m.group(1)}${m.group(2)}',
    );
    text = text.replaceAll(r'$', '');
    return preserveWhitespace ? text : text.trim();
  }
}
Step 8 of 9 • Model Compression & Distillation

The Finale: Distilling Gemma into a Custom SLM Under 150 MB

While an INT4 2B model (~1.2GB) runs well on 4GB–8GB phones, two barriers remain for rural mass adoption across Africa:

  • The 1.2GB Initial Download: Even a one-time 1.2GB download is expensive on prepaid mobile data bundles.
  • 2GB–3GB Android Go Devices: Entry-level phones without NPUs take 5–10 seconds for CPU inference on a 2B model.
Why 150 MB is the Magic Threshold on Android

Google Play's base Android App Bundle (AAB) / install-time asset limit is 150 MB. When you distill your domain-specific Small Language Model (SLM) down to ~134 MB, you can ship the model directly inside the Play Store install or share it offline via Nearby Share / Xender with zero post-install download!

How the Math Works: Getting from 1.35 GB to 134 MB

  1. Teacher → Student Knowledge Distillation: A crop-diagnosis assistant does not need to know how to write C++ shaders or summarize European tax law. We use gemma-2-2b-it (or gemma-2-9b-it) as the Teacher to transfer its domain reasoning on East African agronomy (FAO/IITA + Swahili/Luganda/English/French) into a compact 240M–270M parameter Student SLM.
  2. Vocabulary Pruning (256k → 32k Tokens): Gemma's 256,000-token embedding matrix alone occupies ~260 MB even in INT4! Pruning unused scripts and keeping the top 32,000 domain + East African tokens shrinks the embedding table by 87.5% (down to ~16 MB).
  3. INT4 Block-32 Quantization (dynamic_int4_block32): 240M parameters × 0.5 bytes/weight (120 MB) + 14 MB SentencePiece Tokenizer & Flatbuffer metadata = 134 MB (< 150 MB!).

Part A: PyTorch Logit Distillation Script (Teacher → Student)

Run this Python script on a Colab / Kaggle GPU to distill your Teacher Gemma model into the compact Student checkpoint using combined Cross-Entropy + Soft-Target KL-Divergence Loss:

scripts/distill_gemmea_slm.py PYTHON 
import torch
import torch.nn.functional as F
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer

TEACHER_MODEL_ID = "google/gemma-2-2b-it"      # High-accuracy Teacher
STUDENT_MODEL_ID = "google/gemma-3-270m-it"    # Compact Student (<150MB INT4 target)

tokenizer = AutoTokenizer.from_pretrained(STUDENT_MODEL_ID)
teacher = AutoModelForCausalLM.from_pretrained(
    TEACHER_MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto"
).eval()

student = AutoModelForCausalLM.from_pretrained(
    STUDENT_MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto"
)

class GemmaDistillationTrainer(SFTTrainer):
    def __init__(self, teacher_model, temperature=2.0, alpha=0.5, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.teacher = teacher_model
        self.temperature = temperature
        self.alpha = alpha

    def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
        # 1. Hard-target Cross-Entropy loss on verified FAO/IITA QA pairs
        student_outputs = model(**inputs)
        ce_loss = student_outputs.loss
        student_logits = student_outputs.logits

        # 2. Soft-target Teacher Logit Distillation (KL-Divergence)
        with torch.no_grad():
            teacher_logits = self.teacher(**inputs).logits

        vocab_size = min(student_logits.size(-1), teacher_logits.size(-1))
        T = self.temperature

        kl_loss = F.kl_div(
            F.log_softmax(student_logits[..., :vocab_size] / T, dim=-1),
            F.softmax(teacher_logits[..., :vocab_size] / T, dim=-1),
            reduction="batchmean",
        ) * (T ** 2)

        # Combine hard ground-truth accuracy with teacher's probability distribution
        total_loss = (self.alpha * ce_loss) + ((1.0 - self.alpha) * kl_loss)
        return (total_loss, student_outputs) if return_outputs else total_loss

dataset = load_dataset("json", data_files="fao_iita_east_africa_instruct.jsonl", split="train")

trainer = GemmaDistillationTrainer(
    teacher_model=teacher,
    model=student,
    train_dataset=dataset,
    processing_class=tokenizer,
    temperature=2.0,
    alpha=0.4,
    args=TrainingArguments(
        output_dir="./checkpoints/gemmea-student-270m",
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        learning_rate=2e-4,
        num_train_epochs=3,
        bf16=True,
        logging_steps=25,
        save_strategy="epoch",
    ),
)

trainer.train()
student.save_pretrained("./checkpoints/gemmea-student-merged")
tokenizer.save_pretrained("./checkpoints/gemmea-student-merged")

The 5 Golden Rules for Offline-First Mobile AI in 2026

  1. Stream Downloads to .tmp & Swap Atomically: Never buffer large models in Dart's heap or let interrupted mobile downloads leave corrupted files for the native C++ runtime.
  2. Serialize Native FFI Access: Wrap every flutter_gemma call and stream in a mutex lock (GemmaEngineManager) with deadlock timeouts for Hot Reload resilience.
  3. Downsample Vision Inputs to 512px & Short-Circuit Early: Resize camera photos before tensor encoding, dispose native image handles immediately, and instruct the VLM to halt in Step 1 if the image is out-of-domain.
  4. Choose SQLite FTS5 + BM25 Over Heavy Vector DBs on Budget RAM: Get sub-2ms factual grounding with 0 MB of extra RAM overhead.
  5. Distill & Quantize to <150 MB: Combine Teacher-Student logit distillation, vocabulary pruning, and dynamic_int4_block32 quantization so your AI ships directly inside your app bundle.
