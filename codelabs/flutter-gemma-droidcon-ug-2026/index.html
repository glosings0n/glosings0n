Model Quantization (INT4 vs. INT8) & Atomic Asset Delivery

On a mid-tier 4GB RAM Android phone, Android OS and system services consume ~1.6GB of RAM, and the Flutter UI + Dart VM take ~300MB. That leaves a strict ceiling of ~1.8GB to 2.0GB before Android's Low Memory Killer (lmkd) terminates your app.

Sur un smartphone Android milieu de gamme doté de 4 Go de RAM, le système Android et ses services consomment ~1,6 Go de RAM, tandis que l'interface Flutter et la VM Dart occupent ~300 Mo. Cela laisse un plafond strict de ~1,8 Go à 2,0 Go avant que le Low Memory Killer d'Android (lmkd) ne tue votre application.

~4.0 GB 2B Model in FP16 (Crashes on 4GB RAM)
~2.1 GB 2B Model in INT8 (Zero headroom for Vision)
~1.2 GB E2B in INT4 .litertlm (75% smaller!)
134 MB Distilled 240M SLM in INT4 (See Step 8)
Production Pitfall: Never Put Multi-Hundred-MB Models in Flutter assets/

Bundling a 1.3GB model inside pubspec.yaml assets violates Google Play's 150MB base APK/AAB limit and forces Flutter to copy/decompress the asset on first boot: causing instant OutOfMemoryError crashes on budget phones.

Embarquer un modèle de 1,3 Go dans les assets de pubspec.yaml dépasse la limite de 150 Mo d'un APK/AAB Google Play et oblige Flutter à copier/décompresser l'asset au premier démarrage : ce qui provoque un crash OutOfMemoryError immédiat sur les téléphones d'entrée de gamme.

The Solution: Chunked Streaming + Atomic .tmp Swap

In lib/data/repositories/chat_repository_impl.dart, we stream the quantized .litertlm binary directly to getApplicationDocumentsDirectory() using an IOSink (so Dart's RAM heap stays flat at <5MB). Crucially, we write to gemma.litertlm.tmp first and only rename it to gemma.litertlm when 100% of bytes are on disk. If a user's connection drops at 89%, the native C++ engine will never attempt to memory-map a corrupted binary! (You will paste the complete chat_repository_impl.dart file in Step 7).

Dans lib/data/repositories/chat_repository_impl.dart, nous streamons le binaire quantifié .litertlm directement vers getApplicationDocumentsDirectory() à l'aide d'un IOSink (afin que le tas mémoire Dart reste sous 5 Mo). Point crucial : nous écrivons d'abord dans gemma.litertlm.tmp et ne le renommons en gemma.litertlm qu'une fois 100 % des octets écrits sur le disque. Si la connexion coupe à 89 %, le moteur C++ natif ne tentera jamais de projeter en mémoire (mmap) un fichier corrompu ! (Vous collerez le fichier complet chat_repository_impl.dart à l'Étape 7).

Future<bool> checkModelInstalled() async {
  final directory = await getApplicationDocumentsDirectory();
  final litertlmFile = File('${directory.path}/gemma.litertlm');
  final binFile = File('${directory.path}/gemma.bin');

  // Auto-migrate legacy gemma.bin to gemma.litertlm if already on the user's phone
  if (await binFile.exists() && !await litertlmFile.exists()) {
    await binFile.rename(litertlmFile.path);
  }
  return await litertlmFile.exists();
}

Future<void> initializeGemma(Function(double) onProgress) async {
  return GemmaEngineManager.runWithLock(() async {
    await GemmaEngineManager.ensureInitialized();

    final directory = await getApplicationDocumentsDirectory();
    final modelFile = File('${directory.path}/gemma.litertlm');
    final tempModelFile = File('${directory.path}/gemma.litertlm.tmp');

    if (!await modelFile.exists()) {
      // 1. Clean up any incomplete .tmp file from an interrupted download
      if (await tempModelFile.exists()) {
        await tempModelFile.delete();
      }

      // 2. Fast 4-second DNS check before opening the download stream
      final result = await InternetAddress.lookup('google.com')
          .timeout(const Duration(seconds: 4));
      if (result.isEmpty || result.first.rawAddress.isEmpty) {
        throw const SocketException('Internet connection is required for first-time setup.');
      }

      const url = 'https://huggingface.co/litert-community/'
          'gemma-4-E2B-it-litert-lm/resolve/main/gemma-4-E2B-it.litertlm';
      final client = http.Client();

      try {
        final request = http.Request('GET', Uri.parse(url));
        final response = await client.send(request);
        if (response.statusCode != 200) {
          throw HttpException('Download failed (HTTP ${response.statusCode})');
        }

        final contentLength = response.contentLength ?? 0;
        int downloadedBytes = 0;

        // 3. Stream chunks directly to disk via IOSink (Zero RAM bloat)
        final IOSink sink = tempModelFile.openWrite();
        await response.stream.forEach((chunk) {
          downloadedBytes += chunk.length;
          sink.add(chunk);
          if (contentLength > 0) {
            onProgress(downloadedBytes / contentLength);
          }
        });
        await sink.close();

        // 4. ATOMIC RENAME: Only promote to gemma.litertlm upon 100% completion
        if (await tempModelFile.exists()) {
          await tempModelFile.rename(modelFile.path);
        }
      } catch (e) {
        if (await tempModelFile.exists()) await tempModelFile.delete();
        rethrow;
      } finally {
        client.close();
      }
    }

    // 5. Register the verified local file with FlutterGemma's LiteRT-LM runtime
    await FlutterGemma.installModel(
      modelType: ModelType.gemmaIt,
      fileType: ModelFileType.litertlm,
    ).fromFile(modelFile.path).install();
  });
}
Step 4 of 9 | Native Concurrency & Hardware

Preventing FFI Deadlocks & Hardware Inference: CPU vs. GPU

What Failed in Production #1: Concurrent Native Sessions & Orphaned Isolates

MediaPipe / LiteRT-LM allocates a single native C++ execution graph in memory. During field testing, if a user started a leaf scan and switched to the Chat tab before the scan finished; or if a developer triggered a Flutter Hot Reload while a stream was open: the native FFI channel deadlocked permanently or threw PlatformException(channel-error).

MediaPipe / LiteRT-LM alloue un seul graphe d'exécution C++ natif en mémoire. Lors des tests sur le terrain, si un utilisateur lançait un scan de feuille puis basculait vers l'onglet Chat avant la fin du scan, ou si un développeur déclenchait un Hot Reload Flutter pendant qu'un flux était ouvert : le canal FFI natif se bloquait définitivement (deadlock) ou levait une PlatformException(channel-error).

The Solution: GemmaEngineManager

To make on-device inference rock-solid, we built GemmaEngineManager in lib/core/services/gemma_engine_manager.dart. It serializes all Future and Stream operations through a Completer mutex lock, includes an 8-second deadlock timeout to recover from orphaned Hot-Reload isolates, and automatically resets stale chat session pointers when a native channel error occurs:

Pour rendre l'inférence embarquée infaillible, nous avons conçu GemmaEngineManager dans lib/core/services/gemma_engine_manager.dart. Il sérialise toutes les opérations Future et Stream via un verrou mutex Completer, intègre un timeout anti-deadlock de 8 secondes pour récupérer après un Hot-Reload, et réinitialise automatiquement les pointeurs de session obsolètes en cas d'erreur de canal natif :

  }

  static void resetChatSession() {
    _onResetChatCallback?.call();
  }

  /// Force clears stale lock state and resets chat session on Hot Reload or FFI error
  static void forceResetLockState() {
    dev.log("Force resetting GemmaEngineManager lock state & session handles.");
    _activeExecution = null;
    _initCompleter = null;
    resetChatSession();
  }

  static Future<void> ensureInitialized() async {
    if (_isInitialized) return;
    if (_initCompleter != null) return _initCompleter!.future;

    _initCompleter = Completer<void>();
    try {
      await FlutterEdgeAi.initialize(
        inferenceEngines: const [LiteRtLmEngine()],
      );
      _isInitialized = true;
      _initCompleter!.complete();
    } catch (e) {
      // Native FFI engine already bound across Hot Reload
      _isInitialized = true;
      if (!(_initCompleter?.isCompleted ?? true)) _initCompleter!.complete();
    } finally {
      _initCompleter = null;
    }
  }

  /// Wraps a Future operation to guarantee single-threaded execution on LiteRT-LM
  static Future<T> runWithLock<T>(Future<T> Function() action) async {
    final previousExecution = _activeExecution;
    final completer = Completer<void>();
    _activeExecution = completer.future;

    if (previousExecution != null) {
      try {
        await previousExecution.timeout(const Duration(seconds: 8));
      } on TimeoutException {
        forceResetLockState();
      } catch (_) {}
    }

    try {
      return await action();
    } catch (e) {
      if (e.toString().contains("channel-error") ||
          e.toString().contains("PlatformException") ||
          e.toString().contains("Null")) {
        forceResetLockState();
      }
      rethrow;
    } finally {
      completer.complete();
      if (_activeExecution == completer.future) _activeExecution = null;
    }
  }

  /// Wraps a Stream operation with the same FFI mutex & deadlock protection
  static Stream<T> runStreamWithLock<T>(Stream<T> Function() streamFactory) async* {
    final previousExecution = _activeExecution;
    final completer = Completer<void>();
    _activeExecution = completer.future;

    if (previousExecution != null) {
      try {
        await previousExecution.timeout(const Duration(seconds: 8));
      } on TimeoutException {
        forceResetLockState();
      } catch (_) {}
    }

    try {
      await for (final value in streamFactory()) {
        yield value;
      }
    } catch (e) {
      if (e.toString().contains("channel-error") ||
          e.toString().contains("PlatformException")) {
        forceResetLockState();
      }
      rethrow;
    } finally {
      completer.complete();
      if (_activeExecution == completer.future) _activeExecution = null;
    }
  }

Why CPU First in Gemmea? Three Crucial Field Lessons

While GPU execution offers higher theoretical token throughput, field testing across rural smallholder communities in Uganda revealed three critical architectural bottlenecks that make CPU execution superior for production resilience:

Bien que l'exécution sur GPU offre un débit théorique de tokens supérieur, les tests sur le terrain auprès des petits exploitants agricoles en Ouganda ont révélé trois goulots d'étranglement architecturaux majeurs qui rendent le CPU bien plus résilient en production :

  1. GPU Driver Fragmentation & Silent Crashes: Entry-level and mid-range Android devices (Tecno, Infinix, Samsung Galaxy A, Xiaomi Redmi powered by MediaTek Helio G85/G99 or Unisoc chipsets) run diverse, closed-source GPU drivers (ARM Mali, Imagination PowerVR). Many of these drivers feature incomplete or unstable Vulkan 1.1/1.2 or OpenCL implementations. Attempting to allocate 1.5GB to 2.5GB of model tensors into shared GPU memory triggers native SIGSEGV or EGL_BAD_ALLOC segmentation faults that instantly kill the Linux process without throwing catchable Dart exceptions.
  2. Predictable Memory via Linux mmap: In CPU mode, the LiteRT-LM runtime maps the quantized INT4 .litertlm binary directly into virtual memory via standard POSIX mmap(). The Android kernel pages model weights on demand into system RAM (LPDDR4x/5) without requiring a massive, contiguous block of dedicated VRAM. This prevents sudden terminations by Android's Low Memory Killer (lmkd).
  3. Multimodal Vision Pipeline Reliability: Transferring 512px image tensors between the camera, CPU, and GPU across low-bandwidth 32-bit memory buses frequently causes texture corruption or bus contention. Executing the vision encoder on CPU ensures 100% deterministic mathematical execution.
  1. Fragmentation des pilotes GPU & crashs silencieux : Les smartphones Android d'entrée et de milieu de gamme (Tecno, Infinix, Samsung Galaxy A, Xiaomi Redmi équipés de puces MediaTek Helio G85/G99 ou Unisoc) intègrent des pilotes graphiques propriétaires (ARM Mali, PowerVR) dont le support Vulkan ou OpenCL est parfois partiel ou buggé. Allouer un graphe de 1,5 Go à 2,5 Go en VRAM partagée déclenche des erreurs natives SIGSEGV ou EGL_BAD_ALLOC qui tuent immédiatement le processus sans passer par le bloc try / catch de Dart.
  2. Mémoire prévisible via mmap Linux : En mode CPU, le moteur LiteRT-LM projette le fichier quantifié INT4 .litertlm en mémoire virtuelle via l'appel système POSIX mmap(). Le noyau Android charge les poids à la demande dans la RAM système (LPDDR4x/5) sans exiger de bloc VRAM contigu rigide, évitant ainsi les arrêts brutaux du lmkd (Low Memory Killer).
  3. Fiabilité du pipeline de vision multimodale : Le transfert de tenseurs d'image de 512px entre la caméra, le CPU et le GPU sur des bus mémoire étroits de 32 bits génère des goulots d'étranglement ou des corruptions de textures. L'encodage de vision sur CPU garantit une exécution mathématique 100 % déterministe.

  Future<List<Map<String, dynamic>>> searchFAOKnowledge(String query) async {
    final db = await database;
    final normalized = _stripAccents(query.toLowerCase())
        .replaceAll(RegExp(r'[^a-z0-9\s]'), ' ');
    final terms = normalized
        .split(RegExp(r'\s+'))
        .where((t) => t.length > 2 && !_stopWords.contains(t))
        .toList();

    if (terms.isEmpty) {
      return await db.query('fao_knowledge_base', limit: 3);
    }

    // Primary Path: Native C FTS5 MATCH ordered by BM25 relevance score
    try {
      final ftsQuery = terms.map((t) => '"$t*"').join(' OR ');
      final ftsResults = await db.rawQuery('''
        SELECT k.* FROM fao_knowledge_base k
        JOIN fao_knowledge_fts fts ON k.id = fts.rowid
        WHERE fao_knowledge_fts MATCH ?
        ORDER BY bm25(fao_knowledge_fts) ASC
        LIMIT 3
      ''', [ftsQuery]);

      if (ftsResults.isNotEmpty) return ftsResults;
    } catch (_) {
      // Fallback to weighted field scoring if OEM SQLite lacks FTS5 module
    }

    return await _scoredFallbackSearch(db, terms);
  }

  Future<List<Map<String, dynamic>>> _scoredFallbackSearch(
    Database db,
    List<String> terms,
  ) async {
    final allRows = await db.query('fao_knowledge_base');
    final scoredRows = <Map<String, dynamic>, int>{};

    for (final row in allRows) {
      int score = 0;
      final crop = _stripAccents((row['crop_name'] ?? '').toString().toLowerCase());
      final topic = _stripAccents((row['topic'] ?? '').toString().toLowerCase());
      final keywords = _stripAccents((row['keywords'] ?? '').toString().toLowerCase());
      final content = _stripAccents((row['content'] ?? '').toString().toLowerCase());

      for (final term in terms) {
        if (crop.contains(term)) score += 8;
        if (topic.contains(term)) score += 6;
        if (keywords.contains(term)) score += 4;
        if (content.contains(term)) score += 1;
      }
      if (score > 0) scoredRows[row] = score;
    }

    if (scoredRows.isNotEmpty) {
      final sorted = scoredRows.entries.toList()
        ..sort((a, b) => b.value.compareTo(a.value));
      return sorted.take(3).map((e) => e.key).toList();
    }
    return await db.query('fao_knowledge_base', limit: 3);
  }

  Future<int> updateRainStatus(String date, int isRainy) async {
    final db = await database;
    return await db.update(
      'calendar',
      {'is_rainy': isRainy},
      where: 'event_date = ?',
      whereArgs: [date],
    );
  }

class TextSanitizer {
  static String cleanLatexAndFormatting(String input, {bool preserveWhitespace = false}) {
    if (input.isEmpty) return input;
    String text = input;

    // 1. Convert common LaTeX chemical formulas to farmer-friendly plain text
    text = text.replaceAll(
      RegExp(r'\$?\\?text\{NaHCO\}_?\{?3\}?\\?\$?|\$NaHCO_3\\?\$?', caseSensitive: false),
      'Baking soda (NaHCO3)',
    );
    text = text.replaceAll(
      RegExp(r'\$?\\?text\{H\}_?\{?2\}?\\?text\{O\}\\?\$?|\$H_2O\\?\$?', caseSensitive: false),
      'water (H2O)',
    );

    // 2. Strip LaTeX wrappers and subscript underscores
    text = text.replaceAllMapped(
      RegExp(r'\\(?:text|mathrm|mathbf)\{([^}]+)\}'),
      (m) => m.group(1) ?? '',
    );
    text = text.replaceAllMapped(
      RegExp(r'([A-Za-z]+)_\{?(\d+)\}?'),
      (m) => '${m.group(1)}${m.group(2)}',
    );
    text = text.replaceAll(r'$', '');
    return preserveWhitespace ? text : text.trim();
  }
}

import torch
import torch.nn.functional as F
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer

TEACHER_MODEL_ID = "google/gemma-2-2b-it"      # High-accuracy Teacher
STUDENT_MODEL_ID = "google/gemma-3-270m-it"    # Compact Student (<150MB INT4 target)

tokenizer = AutoTokenizer.from_pretrained(STUDENT_MODEL_ID)
teacher = AutoModelForCausalLM.from_pretrained(
    TEACHER_MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto"
).eval()

student = AutoModelForCausalLM.from_pretrained(
    STUDENT_MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto"
)

class GemmaDistillationTrainer(SFTTrainer):
    def __init__(self, teacher_model, temperature=2.0, alpha=0.5, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.teacher = teacher_model
        self.temperature = temperature
        self.alpha = alpha

    def compute_loss(self, model, inputs, return_outputs=False, **kwargs):
        # 1. Hard-target Cross-Entropy loss on verified FAO/IITA QA pairs
        student_outputs = model(**inputs)
        ce_loss = student_outputs.loss
        student_logits = student_outputs.logits

        # 2. Soft-target Teacher Logit Distillation (KL-Divergence)
        with torch.no_grad():
            teacher_logits = self.teacher(**inputs).logits

        vocab_size = min(student_logits.size(-1), teacher_logits.size(-1))
        T = self.temperature

        kl_loss = F.kl_div(
            F.log_softmax(student_logits[..., :vocab_size] / T, dim=-1),
            F.softmax(teacher_logits[..., :vocab_size] / T, dim=-1),
            reduction="batchmean",
        ) * (T ** 2)

        # Combine hard ground-truth accuracy with teacher's probability distribution
        total_loss = (self.alpha * ce_loss) + ((1.0 - self.alpha) * kl_loss)
        return (total_loss, student_outputs) if return_outputs else total_loss

dataset = load_dataset("json", data_files="fao_iita_east_africa_instruct.jsonl", split="train")

trainer = GemmaDistillationTrainer(
    teacher_model=teacher,
    model=student,
    train_dataset=dataset,
    processing_class=tokenizer,
    temperature=2.0,
    alpha=0.4,
    args=TrainingArguments(
        output_dir="./checkpoints/gemmea-student-270m",
        per_device_train_batch_size=4,
        gradient_accumulation_steps=4,
        learning_rate=2e-4,
        num_train_epochs=3,
        bf16=True,
        logging_steps=25,
        save_strategy="epoch",
    ),
)

trainer.train()

      setState(() => _isBusy = false);

3. Key Engineering Takeaways

  1. Stream Downloads to .tmp & Swap Atomically: Never buffer large models in Dart's heap or let interrupted mobile downloads leave corrupted files for the native C++ runtime.
  2. Serialize Native FFI Access: Wrap every flutter_edge_ai call and stream in a mutex lock (GemmaEngineManager) with deadlock timeouts for Hot Reload resilience.
  3. Downsample Vision Inputs to 512px & Short-Circuit Early: Resize camera photos before tensor encoding, dispose native image handles immediately, and instruct the VLM to halt in Step 1 if the image is out-of-domain.
  4. Choose SQLite FTS5 + BM25 Over Heavy Vector DBs on Budget RAM: Get sub-2ms factual grounding with 0 MB of extra RAM overhead.
  5. Distill & Quantize to <150 MB: Combine Teacher-Student logit distillation, vocabulary pruning, and dynamic_int4_block32 quantization so your AI ships directly inside your app bundle.
  1. Streamer les téléchargements vers .tmp & renommer atomiquement : Ne chargez jamais un modèle entier dans le tas mémoire Dart et ne laissez jamais un téléchargement interrompu exposer un binaire corrompu au moteur C++ natif.
  2. Sérialiser les accès FFI natifs : Enveloppez chaque appel et flux flutter_edge_ai dans un verrou mutex (GemmaEngineManager) avec timeout anti-deadlock pour résister aux Hot Reloads.
  3. Réduire les images Vision à 512px & court-circuiter tôt : Redimensionnez les photos avant l'encodage tensoriel, libérez immédiatement les textures natives et ordonnez au VLM de s'arrêter dès l'Étape 1 si l'image est hors-sujet.
  4. Privilégier SQLite FTS5 + BM25 aux bases vectorielles lourdes sur RAM limitée : Obtenez un ancrage factuel en moins de 2 ms avec 0 Mo de surcharge RAM supplémentaire.
  5. Distiller & quantifier sous 150 Mo : Combinez la distillation de logits Teacher-Student, l'élagage du vocabulaire et la quantification dynamic_int4_block32 pour embarquer votre IA directement dans l'installation Play Store.
