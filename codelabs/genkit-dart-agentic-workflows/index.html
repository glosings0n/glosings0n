Full-Stack Agentic Dart: Building End-to-End Typed AI Agents with Genkit Dart & Shelf

1. Context & The "Why": Why Client-Embedded Cloud LLM Calls Fail in Production

When mobile teams prototype their first cloud-powered AI feature in Flutter, the most common shortcut is calling the Gemini REST SDK directly from the mobile binary. While convenient for a hackathon, shipping direct cloud LLM calls inside a production APK or IPA creates three critical engineering failures:

  1. Credential Extraction & Billing Abuse: Any API key compiled into a mobile binary or passed via --dart-define can be extracted via static decompilation (`strings`, `jadx`) or TLS proxy inspection (`mitmproxy`), exposing your cloud billing quota to unlimited abuse.
  2. Prompt Tampering & Bypassed Business Rules: If the mobile app constructs the system prompt or executes tool callbacks locally, a modified client can spoof tool outputs, bypass regional order quotas, or inject unauthorized discounts.
  3. Schema Drift Between Backend & Mobile: Historically, moving AI orchestration to the backend forced Flutter teams to maintain a Python or Node.js microservice, duplicating JSON serialization logic and breaking compile-time type safety across the wire.

Genkit Dart eliminates this trade-off. You write your AI flows, server-side tools, human-in-the-loop guardrails, and HTTP endpoints in 100% pure Dart on the server, and share the exact same schemantic data contracts with your Flutter client.

1. Contexte & Pourquoi : L'échec des appels LLM Cloud embarqués côté client

Lorsqu'une équipe mobile prototype sa première fonctionnalité IA Cloud dans Flutter, le raccourci le plus fréquent consiste à appeler l'API Gemini directement depuis le binaire mobile. Bien que pratique pour une démonstration rapide, embarquer des appels LLM Cloud directement dans un APK ou IPA de production entraîne trois failles majeures :

  2. Altération des Prompts & Contournement des règles métier : Si l'application mobile construit le prompt système ou exécute les outils localement, un client modifié peut falsifier les réponses d'outils, contourner les quotas régionaux ou s'attribuer des remises non autorisées.
  3. Divergence de schémas entre Backend et Mobile : Historiquement, déporter l'orchestration IA côté serveur obligeait les équipes Flutter à maintenir un microservice Python ou Node.js, dupliquant la sérialisation JSON et brisant le typage fort de bout en bout.

Genkit Dart résout définitivement ce dilemme. Vous développez vos flows IA, vos outils serveur, vos garde-fous avec validation humaine et vos endpoints HTTP en 100% pur Dart côté serveur, tout en partageant exactement les mêmes contrats schemantic avec votre client Flutter.

import 'package:schemantic/schemantic.dart';

part 'agent_contracts.g.dart';

@Schema()
abstract class $OrderAuditInput {
  String get orderId;
  String get sku;

  @IntegerField(
    minimum: 1,
    description: 'Requested unit count for the wholesale order',
  )
  int get quantity;

  @StringField(
    minLength: 2,
    enumValues: ['EAST_AFRICA', 'CENTRAL_AFRICA', 'WEST_AFRICA'],
    description: 'Target fulfillment corridor',
  )
  String get region;

  String? get partnerCode;
}

@Schema()
abstract class $OrderAuditResult {
  String get orderId;
  bool get approved;

  @StringField(
    enumValues: ['APPROVED', 'HOLD_QUOTA_EXCEEDED', 'REJECTED_OUT_OF_STOCK'],

  String get status;

  @IntegerField(
    minimum: 0,
    description: 'Verified units allocated from regional warehouse',
  )
  int get allocatedQuantity;

  double get finalTotalUsd;
  String get reasoningSummary;
}

@Schema()
abstract class $InventoryLookupInput {
  String get sku;
  String get region;

  int get requestedUnits;

import 'package:genkit/genkit.dart';
import 'package:genkit_google_genai/genkit_google_genai.dart';
import 'package:shared_contracts/agent_contracts.dart';

/// Defines a strictly typed order audit flow returning [OrderAuditResult].
Flow<OrderAuditInput, OrderAuditResult, void, void> defineAuditOrderFlow(
  Genkit ai,
) {
  return ai.defineFlow(
    name: 'auditOrder',
    inputSchema: OrderAuditInput.$schema,
    outputSchema: OrderAuditResult.$schema,
    fn: (OrderAuditInput input, _) async {
      final response = await ai.generate(
        model: googleAI.gemini('gemini-2.5-flash'),
        prompt: '''
You are a principal wholesale order compliance auditor.
Audit the following order request using the authoritative server tool `verifyInventoryAndQuota`:
- Order ID: ${input.orderId}
- SKU: ${input.sku}
- Requested Quantity: ${input.quantity}
- Target Corridor: ${input.region}
- Partner Code: ${input.partnerCode ?? 'NONE'}

Rules:
1. Always call `verifyInventoryAndQuota` first to obtain the authoritative stock, quota, and unit price.
2. If the SKU is out of stock (availableUnits < requestedUnits), set approved=false, status='REJECTED_OUT_OF_STOCK', allocatedQuantity=0, finalTotalUsd=0.
3. If requested quantity exceeds maxOrderQuota, set approved=false, status='HOLD_QUOTA_EXCEEDED', allocatedQuantity=maxOrderQuota, and compute finalTotalUsd for the capped allocation.
4. Otherwise set approved=true, status='APPROVED', allocatedQuantity=quantity, and compute finalTotalUsd = quantity * unitPriceUsd.
''',
        toolNames: ['verifyInventoryAndQuota'],
        outputSchema: OrderAuditResult.$schema,
      );

      final structuredOutput = response.output;
      if (structuredOutput == null) {
        throw StateError(
          'Model failed to produce a valid OrderAuditResult schema payload.',
        );
      }
      return structuredOutput;
    },
  );
}

The Server-Side Security Invariant

Never trust the client for prices, quotas, or verification statuses. Notice that OrderAuditInput only accepts orderId, sku, quantity, and region. The mobile client cannot pass a unit price or override a regional quota limit; our server-side Genkit tool resolves those figures directly from the authoritative server ledger before returning context to the model via ToolResult.response(...).

L'Invariant de Sécurité Côté Serveur

Ne faites jamais confiance au client pour les prix, les quotas ou les statuts de vérification. Remarquez que OrderAuditInput n'accepte que orderId, sku, quantity et region. Le client mobile ne peut ni imposer un prix unitaire ni contourner un quota régional ; notre outil Genkit côté serveur interroge directement le registre serveur autoritatif avant de renvoyer le résultat au modèle via ToolResult.response(...).

import 'package:genkit/genkit.dart';
import 'package:shared_contracts/agent_contracts.dart';

/// Authoritative server-side catalog and regional quota ledger.
/// The mobile client never sends prices or quota limits; the server resolves them.
const Map<String, Map<String, Object>> _serverInventoryCatalog = {
  'SOLAR-INV-3KW': {
    'unitPriceUsd': 420.0,
    'stockByRegion': {
      'EAST_AFRICA': 45,
      'CENTRAL_AFRICA': 18,
      'WEST_AFRICA': 30,
    },
    'maxOrderQuota': 20,
  },
  'LFP-BATT-5KWH': {
    'unitPriceUsd': 680.0,
    'stockByRegion': {
      'EAST_AFRICA': 12,
      'CENTRAL_AFRICA': 6,
      'WEST_AFRICA': 15,
    },
    'maxOrderQuota': 10,
  },
};

/// Registers authoritative inventory and partner discount tools on [ai].
void registerInventoryTools(Genkit ai) {
  ai.defineTool(
    name: 'verifyInventoryAndQuota',
    description:
        'Checks authoritative regional warehouse stock, unit price in USD, '
        'and maximum per-order quota for a given SKU and region.',
    inputSchema: InventoryLookupInput.$schema,
    fn: (InventoryLookupInput input, _) async {
      final skuRecord = _serverInventoryCatalog[input.sku.toUpperCase()];
      if (skuRecord == null) {
        return ToolResult.response({
          'found': false,
          'sku': input.sku,
          'error': 'SKU not found in authoritative catalog.',
        });
      }

      final stockMap = skuRecord['stockByRegion']! as Map<String, int>;
      final availableUnits = stockMap[input.region] ?? 0;
      final maxQuota = skuRecord['maxOrderQuota']! as int;
      final unitPriceUsd = skuRecord['unitPriceUsd']! as double;

      return ToolResult.response({
        'found': true,
        'sku': input.sku.toUpperCase(),
        'region': input.region,
        'availableUnits': availableUnits,
        'maxOrderQuota': maxQuota,
        'unitPriceUsd': unitPriceUsd,
        'withinQuota': input.requestedUnits <= maxQuota,
        'sufficientStock': input.requestedUnits <= availableUnits,
      });
    },
  );

  ai.defineTool(
    name: 'applyPartnerDiscount',
    description:
        'Applies a privileged partner discount percentage to an order. '
        'Sensitive state-mutating tool protected by human-in-the-loop approval.',
    inputSchema: PartnerDiscountInput.$schema,
    fn: (PartnerDiscountInput input, _) async {
      final cappedPct = input.requestedDiscountPct.clamp(1, 25);
      return ToolResult.response(
        'Partner discount of $cappedPct% authorized for order '
        '${input.orderId} under partner code ${input.partnerCode}.',
      );
    },
  );
}
Step 5 of 8 | Genkit Middleware & Interruptions

Agent Guardrails & Human-in-the-Loop toolApproval Middleware

Autonomous agents frequently mix read-only tools (like verifyInventoryAndQuota) with high-stakes state-mutating tools (like applyPartnerDiscount, issuing refunds, or modifying files). The official genkit_middleware package provides three composable plugins that you register on your Genkit instance:

  • FilesystemPlugin() + filesystem(rootDirectory: '...'): Sandboxes file reading, writing, and search-and-replace strictly inside an allowed workspace directory.
  • SkillsPlugin() + skills(skillPaths: ['...']): Dynamically loads specialized SKILL.md domain instructions on demand.
  • ToolApprovalPlugin() + toolApproval(approved: [...]): Intercepts any tool call NOT listed in approved, halts the LLM generation loop before the tool body runs, and returns FinishReason.interrupted.

Le paquet officiel genkit_middleware fournit trois plugins composables à enregistrer dans votre instance Genkit :

  • SkillsPlugin() + skills(skillPaths: ['...']) : Injecte dynamiquement des instructions métier spécialisées depuis des fichiers SKILL.md.

/// Read-only `verifyInventoryAndQuota` runs automatically, while
/// `applyPartnerDiscount` triggers `FinishReason.interrupted` for supervisor review.
Flow<OrderAuditInput, String, void, void> defineGuardedDiscountFlow(
  Genkit ai, {
  required Future<bool> Function(ToolRequestPart interrupt) onSupervisorReview,
}) {
  return ai.defineFlow(
    name: 'guardedDiscountAudit',
    inputSchema: OrderAuditInput.$schema,
    outputSchema: SchemanticType.string(),
    fn: (OrderAuditInput input, _) async {
      final response = await ai.generate(
        model: googleAI.gemini('gemini-2.5-flash'),
        prompt: '''
Verify inventory for Order ${input.orderId} (SKU: ${input.sku}, qty: ${input.quantity}, region: ${input.region}).
If partnerCode (${input.partnerCode ?? 'NONE'}) is present, call `applyPartnerDiscount` with a 15% partner discount.
''',
        toolNames: ['verifyInventoryAndQuota', 'applyPartnerDiscount'],
        use: [
          // Read-only lookup is pre-approved; state-mutating discount requires approval
          toolApproval(approved: ['verifyInventoryAndQuota']),
        ],
      );

      if (response.finishReason == FinishReason.interrupted) {
        final interrupt = response.interrupts.first;
        final isApproved = await onSupervisorReview(interrupt);

        if (!isApproved) {
          return 'Order ${input.orderId}: Partner discount tool call '
              '(${interrupt.toolRequest.name}) rejected by supervisor.';
        }

        final resumedResponse = await ai.generate(
          model: googleAI.gemini('gemini-2.5-flash'),
          messages: response.messages,
          toolChoice: ToolChoice.none,
          interruptRestart: [
            ToolRequestPart(
              toolRequest: interrupt.toolRequest,
              metadata: {
                ...?interrupt.metadata,
                'tool-approved': true,
              },
            ),
          ],
        );

        return resumedResponse.text;
      }

      return response.text;
    },
  );
}
Step 6 of 8 | Real-Time SSE Streaming & Shelf

Streaming Flows & HTTP Server with genkit_shelf

A great mobile UX gives users immediate visual feedback while an agent executes multi-step tool calls, and still delivers a strongly typed result at the end. Genkit Dart flows support dual-channel execution:

  • streamSchema: SchemanticType.string(): Defines the type of incremental chunks pushed to the client in real time via context.sendChunk(chunk.text).
  • outputSchema: OrderAuditResult.$schema: Defines the final strongly typed return value resolved when the flow finishes.

To expose flows over HTTP, genkit_shelf provides two patterns:

  1. Custom Shelf Router (shelfHandler(flow)): Mount flows onto specific routes alongside your existing authentication middleware, health checks, or REST endpoints.
  2. Standalone Server (startFlowServer): Boot a dedicated HTTP flow server in one function call.

Une expérience mobile fluide offre à l'utilisateur un retour visuel immédiat pendant que l'agent exécute ses appels d'outils, tout en livrant un résultat fortement typé à la fin. Les flows Genkit Dart prennent en charge ce double canal nativement :

  • streamSchema: SchemanticType.string() : Définit le type des fragments envoyés en temps réel au client via context.sendChunk(chunk.text).
  • outputSchema: OrderAuditResult.$schema : Définit la valeur finale fortement typée retournée à la clôture du flow.

Pour exposer vos flows sur HTTP, genkit_shelf propose deux approches :

  1. Routeur Shelf personnalisé (shelfHandler(flow)) : Montez vos flows sur des routes dédiées aux côtés de vos middlewares d'authentification ou de vos sondes de santé (health checks).
  2. Serveur autonome (startFlowServer) : Démarrez un serveur HTTP dédié aux flows en un seul appel de fonction.

import 'dart:io';
import 'package:genkit/genkit.dart';
import 'package:genkit_google_genai/genkit_google_genai.dart';
import 'package:genkit_middleware/genkit_middleware.dart';
import 'package:genkit_shelf/genkit_shelf.dart';
import 'package:schemantic/schemantic.dart';
import 'package:shared_contracts/agent_contracts.dart';
import 'package:shelf/shelf.dart';
import 'package:shelf/shelf_io.dart' as io;
import 'package:shelf_router/shelf_router.dart';

import 'package:agent_server/flows/audit_flow.dart';
import 'package:agent_server/flows/guarded_action_flow.dart';
import 'package:agent_server/tools/inventory_tools.dart';

Future<void> main() async {
  final apiKey = Platform.environment['GEMINI_API_KEY'];
  if (apiKey == null || apiKey.isEmpty) {
    stderr.writeln('ERROR: GEMINI_API_KEY environment variable is not set.');
    exit(1);
  }

  // 1. Initialize Genkit with Google AI and Middleware plugins
  final ai = Genkit(
    plugins: [
      googleAI(),
      FilesystemPlugin(),
      SkillsPlugin(),
      ToolApprovalPlugin(),
    ],
  );

  // 2. Register authoritative server-side tools
  registerInventoryTools(ai);

  // 3. Register typed and guarded flows
  final auditOrderFlow = defineAuditOrderFlow(ai);
  final guardedDiscountFlow = defineGuardedDiscountFlow(
    ai,
    onSupervisorReview: (interrupt) async {
      stdout.writeln(
        '[HITL Supervisor] Intercepted tool: ${interrupt.toolRequest.name} '
        'with input: ${interrupt.toolRequest.input}',
      );
      return true;
    },
  );

  // 4. Define a real-time streaming flow with chunked narration + final typed output
  final streamOrderAuditFlow = ai.defineFlow(
    name: 'streamOrderAudit',
    inputSchema: OrderAuditInput.$schema,
    outputSchema: OrderAuditResult.$schema,
    streamSchema: SchemanticType.string(),
    fn: (OrderAuditInput input, context) async {
      final stream = ai.generateStream(
        model: googleAI.gemini('gemini-2.5-flash'),
        prompt: '''
Stream a concise, real-time compliance log while auditing Order ${input.orderId}
(SKU: ${input.sku}, quantity: ${input.quantity}, corridor: ${input.region}).
Call `verifyInventoryAndQuota` to inspect stock and quota constraints.
''',
        toolNames: ['verifyInventoryAndQuota'],
      );

      await for (final chunk in stream) {
        if (chunk.text.isNotEmpty) {
          context.sendChunk(chunk.text);
        }
      }

      return auditOrderFlow(input);
    },
  );

  // 5. Mount Genkit flows onto a custom Shelf Router alongside health probes
  // (Alternatively, call `await startFlowServer(flows: [...], port: 3400);`)
  final router = Router()
    ..get('/healthz', (Request req) => Response.ok('{"status":"ok"}'))
    ..post('/auditOrder', shelfHandler(auditOrderFlow))
    ..post('/streamOrderAudit', shelfHandler(streamOrderAuditFlow))
    ..post('/guardedDiscountAudit', shelfHandler(guardedDiscountFlow));

  final handler = const Pipeline()
      .addMiddleware(logRequests())
      .addHandler(router.call);

  final port = int.parse(Platform.environment['PORT'] ?? '3400');
  final server = await io.serve(handler, InternetAddress.anyIPv4, port);
  stdout.writeln(
    'Genkit Shelf Agent Server listening on http://${server.address.host}:${server.port}',
  );
}

2. Key Engineering Takeaways

  1. Single-Language Full-Stack Velocity: Sharing a pure Dart schemantic package across your Shelf server and Flutter client eliminates manual DTO synchronization and runtime casting errors.
  2. Authoritative Server-Side Tools: Keep API keys, pricing catalogs, and quota ledgers exclusively inside server-side ai.defineTool handlers returning ToolResult.response(...).
  3. Deterministic Guardrails with toolApproval: Never let an LLM execute state-mutating tools unchecked; use ToolApprovalPlugin() to trigger FinishReason.interrupted and require explicit supervisor sign-off before resuming with interruptRestart.
  4. Dual-Channel Streaming UX: Combine streamSchema + context.sendChunk() for sub-second streaming progress with outputSchema + stream.onResult for a guaranteed structured final payload.

2. Points clés à retenir

  1. Vélocité Full-Stack en un seul langage : Partager un paquet pur Dart schemantic entre votre serveur Shelf et votre client Flutter élimine toute désynchronisation de DTO et les erreurs de typage à l'exécution.
  2. Outils Serveur Autoritatifs : Conservez les clés API, les catalogues de prix et les quotas exclusivement dans des gestionnaires ai.defineTool côté serveur retournant ToolResult.response(...).
  3. Garde-fous déterministes avec toolApproval : Ne laissez jamais un LLM exécuter des outils modifiant l'état sans contrôle ; utilisez ToolApprovalPlugin() pour déclencher FinishReason.interrupted et exiger une validation explicite avant reprise via interruptRestart.
  4. Expérience Streaming à double canal : Combinez streamSchema + context.sendChunk() pour l'affichage en direct et outputSchema + stream.onResult pour garantir un résultat final structuré.
